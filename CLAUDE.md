# HairRate — правила для Claude

Сайт оценки причесок. Статические файлы на GitHub Pages + Supabase (вход, база, фото).
Владелец — Степан. Интерфейс и все тексты — на русском.

## Устройство

- `index.html`, `style.css`, `script.js` — весь сайт, без сборки и без внешних библиотек.
  Клиент к Supabase написан на `fetch` (auth, REST, storage) — так и оставлять.
- `config.js` — адрес проекта Supabase и публичный ключ. **Не менять.**
- `supabase/setup.sql` — схема базы, правила доступа (RLS), хранилище фото. Это источник правды
  для схемы: всё, что применено к базе, должно быть в этом файле. Повторный запуск должен быть безопасным.
- Боевая база — проект Supabase `xrelxjehbwxzffurezxi`. Доступ к ней — через коннектор Supabase
  (инструменты вида `execute_sql`, `apply_migration`, `list_tables`). Другие проекты не трогать.
- `tests/run.sh` — автотесты: поднимает локальную копию Supabase (Postgres + PostgREST + шлюз из
  `tests/gateway.py`), применяет `setup.sql` дважды, сверяет формулу на всех 7290 комбинациях
  и прогоняет сайт в браузере (`tests/e2e.js`).
- `IDEAS.md` — очередь улучшений. `CHANGELOG.md` — журнал изменений.

## Жёсткие правила

1. **Формулу оценки не трогать никогда**: `calculateScore` в `script.js` и `public.hairrate_score`
   в `setup.sql` (4–67, `0.2/0.2/0.2/0.4`, округление как `Math.round`). Тест сверки формулы должен проходить.
2. **Стиль — минималистичный чёрно-белый.** Тёплые серые, шрифт Inter, никаких цветных акцентов.
   Все цвета — только через токены в `:root` и их тёмные варианты (обе темы). Новые элементы
   должны выглядеть как существующие: те же радиусы, отступы, кнопки.
3. **Ничего не удалять из того, что работает**, без явной просьбы владельца.
4. **Безопасность**: любой пользовательский текст выводить через `escapeHtml`; права проверяет база (RLS),
   интерфейс только прячет недоступное. Никаких секретных ключей в репозитории.
5. **Изменения базы** — только добавочные и идемпотентные правки в `supabase/setup.sql`
   (`if not exists`, `drop policy if exists` и т. п.). Сайт обязан работать и со старой, и с новой схемой
   (запасной путь, как для `legacy_author` в `apiLoadAll`), потому что база меняется раньше, чем
   владелец примет PR.
6. **Телефон**: на ширине 375 px нет горизонтальной прокрутки, в светлой и тёмной теме.
7. **Перед любым PR `bash tests/run.sh` обязан пройти.** Для новой функции — добавить проверку в `tests/e2e.js`.

## Работа с боевой базой

Разрешено:
- читать схему и данные, чтобы проверить состояние (`list_tables`, `select`);
- применять **добавочные** изменения: новые таблицы, колонки, индексы, функции, правила RLS, `grant`.
  Порядок: правка в `supabase/setup.sql` → `bash tests/run.sh` проходит → тот же SQL применить через
  `apply_migration` (имя вида `hairrate_ГГГГММДД_тема`) → проверить, что сайт читает новое как гость:
  `begin; set local role anon; select … limit 1; rollback;`.

Запрещено, без исключений:
- `drop table`, `drop column`, `truncate`, `delete`/`update` пользовательских данных
  (`profiles`, `hairstyles`, `reviews`, `storage.objects`), отключение RLS, ослабление правил доступа;
- любые изменения схем `auth` и `storage` кроме правил для бакета `photos`, настройки входа и почты;
- пауза, удаление, создание проектов, всё платное (`create_project`, `confirm_cost` и т. п.);
- данные участников (почты, ники, оценки) — не копировать в репозиторий, PR и сообщения: репозиторий публичный.

Если для задачи нужно что-то из запрещённого — не делать, а описать в PR, что и зачем нужно, и
оставить решение владельцу.

## Как работать в автозапуске

- Одно небольшое законченное улучшение за запуск. Брать из `IDEAS.md`: сначала раздел
  «От владельца», затем «Очередь» сверху вниз. Можно предложить и своё, если оно явно полезнее.
- Не браться за пункт, если в репозитории уже есть открытый PR от Claude на эту же тему.
- Отдельная ветка `claude/<коротко-о-задаче>`, pull request в `main` с описанием по-русски:
  что сделано, как проверить, скриншот или его описание, что изменено в базе (если изменено).
- Pull request открывать через REST API: `gh api repos/stepanstoliarzh/hair/pulls -X POST -f title=… -f head=… -f base=main -F body=@файл`
  (`gh pr create` и другие GraphQL-команды в облачных сеансах не работают). Список PR —
  `gh api "repos/stepanstoliarzh/hair/pulls?state=open"`.
- В том же PR: отметить пункт в `IDEAS.md` как сделанный и добавить запись в `CHANGELOG.md`.
- Если тесты не проходят и починить не удаётся — PR не открывать, сообщить, что сломалось.
